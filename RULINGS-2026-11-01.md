## Review of T4-08 and the shift money boundary (lane B, landed on `main` 1 Nov 2026)

Read, not executed: migration `0190_one_time_rider_links.sql`, `supabase/functions/rider-link/index.ts`, and a skim of `0186_shift_handovers.sql`. For Babin to pass to lane B — Claude does not edit another lane's files.

| # | Finding | Why it matters | Suggested fix |
|---|---|---|---|
| R1 | The three rider-facing RPCs are `grant execute … to authenticated, service_role`, but the Edge Function calls them with the **service role** only | Once email sign-up opens (D29), any stranger's session can call them directly, bypassing the Edge Function. They take the token **hash** as the credential, and the staff SELECT policy on `delivery_job_links` lets staff read `token_hash` | Grant those three to `service_role` only; exclude `token_hash` from the staff SELECT (column grant or view) |
| R2 | `create_rider_link` carries no `client_uuid` and the table has none (Law 8) | A double-tap issues two live links for one job | Add `client_uuid` unique, return the existing link on replay |
| R3 | The browser generates the raw token and sends its hash; the server cannot check the token's entropy | A faulty client could register a guessable hash | Generate the token in the Edge Function (CSPRNG) and return the raw value once |
| R4 | Error text differs for unknown / revoked / expired / completed links | Tells a holder of a once-valid token which state it is in; low risk at 128 bits | Optional: one generic message to the rider, keep detail in the audit row |

Skim of 0186: cash lives in `shift_handover_finances` behind `auth_can_view_money()`, the view masks it for money-blind roles, UPDATE/DELETE are revoked — no problem seen; **lifecycle gates were not run** against it by this review.
