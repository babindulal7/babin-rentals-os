# Rulings — 24 October 2026

## Committed Return and independent cleaning/QC/Reset tasks

Babin's Booking Operations brief v1.1 explicitly rules that individually verified, physically received usable units become bookable after a successful persisted Return, even while Cleaning, QC or Reset tasks are pending. Partial Return can keep the parent booking On Rent. Actual damage/loss, maintenance, retirement and conflicting reservations remain exclusions. Reset completion is read from task records; it neither advances the rental stage nor creates the initial availability event.

This product ruling does not authorize hosted changes. The same brief explicitly prohibits migrations. The disposable local reservation probe shows that the current database still retains the original unit hold after a partial Return. Local migration-authoring clarification was requested; no permission is inferred from the product ruling, no hold is hidden from availability reads, and no migration was authored/applied in this pass. Evidence: `artifacts/booking-operations-20261024/reservation-contract-probe.json`.

## Integrate the guarded operations-branch pair

Babin explicitly selected **“Integrate the guarded pair”** after being shown the 0171 defaults and Admin boundary. This approves local shared-source integration of guarded 0171 + 0172, not hosted migration application, deployment or physical acceptance.

- No grant history for a user/operation retains existing role-based global access. Any active or revoked history scopes that user/operation to active branch grants. Revoking the last active grant denies every branch; reissue can restore a specific branch.
- Owner/Admin issue and revoke grants; Admin cannot modify Owner/Admin grants, including self. Preserve the direct authenticated table-write revocation already present in the shared 0171.
- Booked work uses the booking branch. Per Babin's earlier explicit choice, unbooked Reset work uses `product_units.warehouse_id → warehouses.branch_id`, resolved at write time. No actor-home or stale unit-branch fallback.
- Reset queue/task writes are checked by restrictive RLS for both old and new scope; early action checks also run in mock mode with an explicit mock implementation. Existing role policies remain necessary, with no new money-visible role or delete permission.
- `npm run check:security` must include the grant-history and Reset direct-write/reparenting regressions through the existing CI security step. This prevents syntax-only rebuilds from hiding the reproduced Reset bypass.

The approved queue insertion boundary also applies when Return creates cleaning work. A scoped operator performing that workflow needs Reset scope as well as Return scope on the affected branch. Return scope alone is not a Reset authorization; the regression tests both refusal and the paired-grant positive control. Do not claim the multi-write Return action is made atomic by this policy.

Changed at: `0171_operations_branch_grants.sql`, `0172_reset_branch_write_boundary.sql`, `floorVerb.ts` and its mock/tests, security scripts, `package.json`, CI and `PERMISSIONS.md`. Revert = review a forward local change to the scope boundary and matching tests; preserve grant history and all existing records. No destructive live rollback is authorized.
