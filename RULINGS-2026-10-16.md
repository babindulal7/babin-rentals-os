## Client import recovery verification

The user authorized completion of client import recovery, phone usability and release verification. This implements the existing immutable per-row receipt contract from the 13 October import ruling; permissions, client fields and save RPC remain unchanged.

- A recovered device draft is a hint. On resume, all immutable batch requests are replayed against server receipts before their rows count as confirmed. Device-stored success labels never substitute for server confirmation.
- The original payload and UUID are preserved through retries. UUID uniqueness follows PostgreSQL's case-insensitive UUID representation. The action snapshots scalar payloads before asynchronous directory checks so later caller changes cannot alter a request associated with a receipt key.
- Recovery is written before the first save. If storage fails during progress, the current request can finish but later rows stop. Retrying retains the original keys.
- Phone preview rows expose identity, selection and status in the existing responsive layout, with explicit field labels. No new design system or permission rule is introduced.

Implementation: `clientImportRecovery.ts`, `importClients.ts`, `ImportCenter.tsx` and `import-center.css`. Reversal: revert the corresponding recovery/replay safeguards together; never reuse a receipt key for a changed payload.

Remote staging and deployment remain conditional on an identified staging project, role credentials, deployment target and backup proof under `BACKUP_PROTOCOL.md`. Local mock/PGlite evidence does not certify JWT/PostgREST behavior. No live migration may be applied by an agent (N-5).
