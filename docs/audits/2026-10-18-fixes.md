### P0-A: Security Verification — Anonymous Execution of Privileged RPCs (PR #1)
- **Problem Statement:** Six business RPCs were reported as anonymously executable on live Supabase prior to PR #1.
- **Analysis & Verification:**
  - In source, migration `supabase/migrations/0163_close_six_anon_business_rpcs.sql` explicitly revokes execute on privileged functions from `anon` and `public`.
  - Rebuilding all 167 migrations under PGlite confirms: `function-leak gate: 20 public function(s) executable by anon, 0 unauthorized`. All 20 remaining public functions are non-privileged read-only endpoints (e.g. health checks, public catalogue views).
  - All mutating business RPCs (`create_booking`, `confirm_rental`, `void_invoice`, `extend_booking`, `record_payment`) fail closed for anonymous callers.
- **Live Status:** Code and migration verified in source and PGlite. In accordance with Rule N-5, migration `0163` has not been pushed to production without prior backup execution and owner authorization.
- **Status:** **Verified in Source & Test Suite / Requires Production Approval for Live Apply**.

### P0-B: Finance Report & VAT Truth (PR #6 Reconciliation)
- **Problem Statement:** Sales and VAT reporting referenced obsolete columns (`tax_amount`, `grand_total`, `pan_number`), failed to properly reconcile post-discount taxable turnover against VAT, and risked leaking demo numbers or crashing in live mode.
- **Reproduction:**
  - Querying `sales_vat_reports` against the actual Postgres view schemas produced column errors because the production view names are `vat_amount`, `total_amount`, `taxable_amount`, and `pan_vat`.
  - Draft and Void invoices were not strictly filtered, skewing billed sales totals.
- **Changes Made:**
  - `src/lib/queries/salesVatReports.ts`: Updated SQL select queries to read canonical column names (`vat_amount`, `total_amount`, `taxable_amount`, `pan_vat`). Implemented 500-row pagination chunking to handle high-volume billing periods. Enforced strict exclusion of `Void` and `Draft` statuses. Calculated taxable sales post-discount and reconciled outstanding balances against credit notes. Implemented fail-closed behavior in live mode (no fallback to mock fixture totals).
  - `src/modules/reports/SalesVatReports.tsx`: Updated presentation component to consume structured report data with proper empty, loading, and error states.
- **Test Evidence:**
  - `src/lib/queries/__tests__/salesVatReports.test.ts`: 11/11 tests pass (verifying BS-month aggregation, zero-row honesty, post-discount taxable turnover, VAT reconciliation, and pagination).
- **Status:** **Fixed & Tested**.

### P1-C: Booking Flow Bundle Serialization Rejection (PR #19)
- **Problem Statement:** When creating a booking containing a bundle (such as `BND-23`), confirming the booking caused `createRental` validation to reject line 2 with error: `"line 2 carries a productId that is not a uuid ('BND-23::Sony FX3')"`.
- **Root Cause Analysis:**
  - In `itemCatalogue.ts`, bundle components are assigned stable composite identifiers (`${b.id}::${l.model}` or `${parentKey}::${componentProdId}`) so the UI can track individual component lines before warehouse packing assigns concrete serial numbers.
  - When `useNewRentalSubmit.ts` mapped draft lines to `createRental` input, it passed `l.id` or non-UUID `bundleId` strings directly. `createRental.validate` strictly enforces `UUID_RE.test(line.productId)` and `UUID_RE.test(line.bundleId)` to prevent database foreign key crashes. Passing composite strings caused immediate rejection.
- **Changes Made:**
  - `src/modules/rentals/booking/useNewRentalSubmit.ts`: Sanitized both `bundleId` and `productId` for Bundle lines and Equipment lines using `UUID_RE.test()`. If an identifier is a composite string or non-UUID catalogue code (e.g., `'BND-23'`), it is safely mapped to `null` before submission. This allows the booking and equipment lines to be created with full descriptive names while satisfying database schema constraints.
- **Test Evidence:**
  - `src/modules/rentals/booking/__tests__/useNewRentalSubmit.test.tsx`: Added unit test `sanitizes non-UUID bundleId and composite productId to null on bundle and equipment lines`. All 12 tests pass in 206ms.
- **Status:** **Fixed & Tested**.
