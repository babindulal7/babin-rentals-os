# T1-19 — Speed with five years of data

Work only in `lane-a/T1-19-volume-baseline`, one agent per checkout. Read `docs/00_READ_FIRST.md`, CLAUDE, the T1-19 card in `docs/plans/T1_RELEASE.md`, `docs/ARCHITECTURE.md`, and `src/lib/queries/` to find the exact query each screen sends.

Write `scripts/seed-volume.mjs` (`seed:volume`) and `scripts/check-volume.mjs` (`check:volume`). Both connect with `pg` to the local Supabase Postgres only and exit with an error on any other host (N-5). The seed uses a fixed random seed so two runs give the same data, inserts in batches, respects every constraint (no overlapping reservations for one unit), and never disables a trigger or the GiST constraint. Target: 3 branches, 5,000 units, 2,000 clients, 60,000 bookings across five years with lines, reservations, transitions, invoices and payments.

`check:volume` sets the JWT claims of a seeded Coordinator and a seeded Warehouse user so RLS applies, runs the query behind each screen named in the card with `EXPLAIN (ANALYZE, BUFFERS)`, three times each, and writes the median time, row count and whether a sequential scan on a large table appeared to `docs/reference/VOLUME_BASELINE.md`.

Budgets ⭐ (Babin to confirm): lists and search under 300 ms, availability under 150 ms, reports under 2 s. Do not add indexes or rewrite queries here. List each query over budget with its plan and a proposed fix; each becomes its own card with its own migration number from `MIGRATION_LEDGER.md`.

Run `npm run gates`, then the two scripts on a fresh local stack. Update PROGRESS with the measured table, generated completion and Remaining; run `lint:progress`. Status is ready until Babin merges. Never write done while awaiting merge.
