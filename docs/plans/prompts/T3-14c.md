### 2. Number inside the transaction that triggers it

`issue_invoice` must be called **from the server-side path that already owns the transaction**, never as a second browser round trip:

- `full_payment` / `first_payment`: inside the payment path — the settle-and-issue happens in **one** SQL transaction. Replace or wrap the client-side sequence in `src/actions/finance/recordPayment.ts`, which today mints `payment_no` over the wire (`:391-400`) and then inserts (`:402-426`). Copying that shape for invoices would burn an `INV-` number on every retry (`0086:88-91`, audit F8).
- `handover`: inside the handover transition, which is already a fail-closed RPC (`apply_booking_stage_transition`).
- If the number cannot be minted, the **whole** triggering action fails. A payment that posts with an un-numbered invoice when the rule says "number now" is a silent accounting defect, not a partial success.

**Assertions:** settle → exactly one number, `order_number_sequences` advanced by exactly 1; retry the same settlement (Law 8 key) → one number, sequence unchanged; a second issue attempt → named refusal.
